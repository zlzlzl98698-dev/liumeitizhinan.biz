## 第一章：为什么必须先谈“纯专属客户端模式”？（决定你该不该买的第一道门槛）

与多数把重点放在带宽跑分的常规评测不同，剖析飞猫云的第一章节必须从客户端架构讲起——因为一旦买错架构，哪怕网速再快也会与您的设备生态格格不入。

### 1.1 飞猫云的极简设计逻辑
在《推广机场品牌清单.txt》中，飞猫云反复强调三大产品定位：“专属客户端下载登录即用”“不用配订阅”“不用自己挑客户端、导订阅”。对于只用一台笔记本和一部手机、连 YAML 与规则模式都不想搞懂的普通用户而言，这种设计的实际痛点解决率极高：
- **不会遇到“订阅更新返回 200 但内容为空”或“User-Agent 不兼容”故障**；
- **不会因为不会安装Clash Service Mode 与 TUN 虚拟网卡，导致桌面软件卡在系统代理死角**；
- **不会在误用陌生网页订阅转换站时泄露 Token 链接**。

*(校注说明：早期站内自动解析程序曾因文字中出现“Clash”关键词误判过第三方兼容性；我们在本次核实审校中已将 [飞猫云商业档案](/brands/feimao/) 与数据库修正为 **纯专属客户端模式 / 不提供第三方订阅**，确保读者不被错误引导。)*

### 1.2 为“省事”付出的 4 项长期生态代价
然而，没有通用订阅链接在另一群用户眼里就是明显硬伤：
1. **无法进路由器与电视盒子**：家里配了 OpenWrt（OpenClash / Nikki / HomeProxy）全屋代理、或者客厅用 Apple TV 装 Stash / 小火箭看 4K Netflix，飞猫云完全接不进去。
2. **无法写 AI 单节点防封号脚本**：您无法在桌面端像 Clash Verge Rev 那样编写 `Select` 固定分组把 Anthropic/Claude 强行锁在单一美国出口上（即官方客户端切不切节点由软件默认行为控制）。
3. **跨平台依赖官网 App 维护度**：如果 iOS 端采用企业签名或海外区商店审核调整导致 App 短期掉签或更新滞后，您手头没有通用的 Shadowrocket 备用通道可切换。
4. **失去“混合双订阅灾备”便利性**：习惯把主力和备用机场节点塞进同一个 Clash 配置文件里一键切换的玩家，使用飞猫云只能单独再开一个软件切换。

# 晚高峰卡顿与延迟过高优化

**Answer-First 核心结论**：白天飞快而每晚 **20:00–23:00** 延迟翻倍、视频转圈或 AI 断流，根源在于 **跨网国际出口晚高峰拥堵、同节点并发拥挤，或运营商针对特定入口/UDP 协议施加 QoS 限速**。

优化晚高峰体验应按以下三步操作：
- **① 绕开热门拥挤地区**：香港高峰拥堵时，及时切换日本、新加坡、台湾或同地区冷门编号节点。
- **② 区分路由与协议**：对比不同运营商入口，并在 TCP（VLESS/Trojan）与 UDP（Hysteria 2）协议间实测切换。
- **③ 排除本机抢占**：暂停后台网盘同步与大文件下载，并区分 [部分节点超时](/troubleshooting/partial-nodes-timeout/) 与全局链路问题。

## 一、晚高峰卡顿与丢包拥堵：10 秒症状定位矩阵

| 症状现象 | 本质原因 | 优先处理方向 |
|---|---|---|
| 晚上所有香港节点都慢，但日本/新加坡节点流畅 | 香港单向出口或该组共享落地并发过载 | 切换日本、新加坡或编号靠后的备用节点 |
| 只有特定某 1–2 个节点晚高峰丢包严重，其余正常 | 单台落地机被大流量滥用或当地线路维护 | 换同地区其他节点，参考 [部分节点超时排查](/troubleshooting/partial-nodes-timeout/) |
| 视频勉强能看但延迟极高、协议切换后差异巨大 | 所在宽带在晚高峰对 UDP 或特定端口进行了 QoS 限速 | 对比切换 TCP 与 Hysteria 2 节点，改用专线入口 |
| 不仅代理卡，连直连国内测速也明显掉速 | 本地路由器负载过高、2.4G Wi-Fi 干扰或全家抢带宽 | 改连 5GHz Wi-Fi / 网线，暂停后台云备份与下载 |

## 二、晚高峰实操优化步骤

### 1. 先做本地环境与带宽抢占隔离
1. **检查内网占用**：先确认电脑或同 Wi-Fi 下的设备没有开启百度网盘、OneDrive、iCloud 照片同步、Steam 更新或 BT/PT 下载，这些后台任务会瞬间占满上行带宽并把所有代理请求挤到高延迟队列；
2. **排查无线信号干扰**：晚间邻居路由器同时活跃，2.4GHz 频段极易出现高抖动。将设备切换到 5GHz Wi-Fi 或直接插网线，或切换手机 5G 热点对比测试（参见 [Wi-Fi 与蜂窝网络排查](/troubleshooting/wifi-vs-cellular/)）。

### 2. 科学换线：避开单一热门节点与低质量直连
1. **跨编号与跨地区试错**：不要死守 `香港 01`！当晚高峰拥堵时，按顺序测试同一机场内的 `香港 05/08`、`新加坡`、`日本` 或 `台湾` 节点；
2. **优先选择中转或专线架构入口**：如果订阅中标注了不同运营商入口（如移动/联通/电信入口或 BGP 中转、IEPL 专线），优先选择匹配您当前宽带的入口组。关于不同传输架构在晚高峰的抗丢包差异，可查看 [**IEPL 与 IPLC 专线百科 →**](/network/iepl-vs-iplc/) 与 [**三大运营商国际出口路由差异 →**](/network/three-isp-routing/)；
3. **验证协议适配性**：如果订阅同时提供 VLESS/Trojan（TCP）和 Hysteria 2（UDP）节点，晚高峰期间各自连续播放 2 分钟 4K 视频对比缓冲速度——部分地区移动/电信晚间对 UDP 限速时，切回常规加密 TCP 隧道反而更稳定。

### 3. 调整客户端并发与规则策略
- **关闭高频自动测速**：在 Clash Verge Rev / v2rayN 中，把自动测速间隔拉长或关闭不必要的全节点批量测速，避免几百次并发握手加重路由器负担；
- **确保模式为 Rule（规则）**：切忌误开 `Global（全局）`，否则所有国内软件升级和高清流媒体也会绕道拥堵的海外节点，既耗流量又拖慢总带宽。

## 三、晚高峰卡顿与丢包拥堵：恢复验收标准

- 在晚高峰 **20:30–22:00** 之间，用 Edge 或 Chrome 打开 YouTube 播放一段 4K 60fps 测试视频，右键「详细统计信息」确认 `Connection Speed` 稳定保持在 25,000 Kbps 以上、连续观看 5 分钟不自动降画质；
- 如果您按照上述步骤切换所有节点在晚高峰依然卡死在 5Mbps 以下，则说明当前套餐的跨境承载能力已见顶，可参考 [**中转与直连技术对比 →**](/network/bgp-transit-vs-direct/) 与 [**流媒体播放优化指南 →**](/guides/streaming-optimization/) 评估网络选型。

# Wi-Fi 连不上节点但手机 5G 流量可以连接怎么排查？6 个本地网络拦截定位方法

**Answer-First 核心结论**：只要手机切到 5G/4G 移动数据后同一套机场节点瞬间可用，**就已经 100% 排除了机场跑路、套餐到期或节点全挂的可能**——问题必定出在您此刻连着的 **Wi-Fi 本地路由或宽带出口** 中。

五大高发本地故障元凶按概率排序：
- **路由器与协议层**：① **Wi-Fi 路由器分配了畸形 IPv6 或被污染的本地 DNS**；② **公司/校园网防火墙封锁非 443 端口或拦截 UDP/Hysteria2 协议**；③ **家里光猫/路由器 NAT 死锁或开启了过严防火墙**。
- **设备与嵌套层**：④ **手机设置了冲突的 Wi-Fi 静态 HTTP 代理/私有 DNS**；⑤ **当前 Wi-Fi 连在另一台已配置软路由的设备上造成套娃拦截**。

---

## 一、第一步：区分是“家用宽带 Wi-Fi”还是“公司/学校公共 Wi-Fi”

不同环境的策略拦截机制截然不同，请先对号入座：

| 当前所处的 Wi-Fi 类型 | 最可能存在的阻断源 | 首选切入步骤 |
|---|---|---|
| **自己家里的光纤 Wi-Fi** | 路由器/光猫 NAT 状态卡死、ISP 下发缺陷 IPv6 劫持 DNS、或误配手动 DNS | **执行步骤 1、2、3** |
| **公司办公网 / 校园网 / 酒店 Wi-Fi** | 商业防火墙封堵非标端口、阻断 UDP（影响 Hysteria 2/TUIC）、强制 Web 认证页拦截 | **执行步骤 4、5、6** |

---

## 二、6 项精确排查与一键修复动作

### 第 1 步：重启家庭光猫与主路由器（解决 50% 家用突发异常）
家庭网络连续运行几周后，廉价光猫极易出现 UDP NAT 会话表溢出、或者特定省市宽带临时分配了一段出海故障的 IP 段。
- **操作**：直接拔掉家里光猫与 Wi-Fi 路由器的电源插头（不只点网页软重启），静置 **30 秒后重新通电**，触发宽带重新 PPPoE 拨号并刷新路由本地 DNS 缓存。

### 第 2 步：关闭设备连接该 Wi-Fi 下的“IPv6 泄露与手动残留代理”
很多家用宽带在光猫后台默认给 Wi-Fi 设备派发了原生 IPv6 地址，而 5G 网络下您的代理 App 可能走了更干净的 IPv4 处理逻辑：
- **排查方式**：进入手机/电脑当前 Wi-Fi 详情设置：
  - 查看 **HTTP 代理（Configure Proxy）** 是否不小心填了以前测试遗留的 `手动` IP 端口（比如以前用电脑开共享代理填的 `192.168.1.x:7890`），将其改回 **`关闭（Off）`**；
  - 在客户端（Clash Verge Rev / Shadowrocket）内部将 `IPv6` 选项关闭；若有管理家里路由器权限，在测试排查期间可临时关闭路由器的 IPv6 LAN 派发做对比测试（原理参考 [IPv6 泄漏故障排查](/troubleshooting/ipv6-leak-error/)）。

### 第 3 步：检查 Wi-Fi 的 DNS 设置（排查本地运营商 DNS 劫持）
若机场节点的中转入口用的是**域名**而非纯数字 IP，国内某些地区的家用宽带 DNS 会在特定时段污染或超慢解析该中转入口域名，而移动 5G 的 DNS 恰巧没有污染它，从而表现为“5G 能连、Wi-Fi 全超时”。
- **操作**：在手机或电脑对应 Wi-Fi 设置里把 DNS 从默认自动改为可信公共 DNS（如 `223.5.5.5` 与 `119.29.29.29` 仅测试能否顺畅握手机场入口域名），随后刷新一次节点列表测速；或在代理客户端将本地 `nameserver` 指定可靠国内 DoH（参考 [DNS 解析错误排查](/troubleshooting/dns-resolution-error/)）。

### 第 4 步：公司网/校园网环境——立刻避开 UDP 协议与奇葩端口，专挑 `443` TCP 节点
这是职场与学生宿舍最普遍的痛点：校园网和企业审计网关常常会做两件事：
1. **一刀切封死除 `80 / 443` 以外的所有高位数 TCP 端口**；
2. **完全丢弃高速 UDP 大流（直接掐死 Hysteria 2、TUIC、WireGuard）**。
- **应对做法**：在客户端节点列表里看节点详情或更换节点——优先切换基于 **标准 `443` 端口的 `VLESS / Trojan`（TLS 伪装）节点**；如果在公司网用 Clash，尽量关闭激进 UDP 转发测试 TCP 网页连通，往往瞬间打通！

### 第 5 步：排查是不是连着了“已经开着旁路由/插件的家里 Wi-Fi”导致双重代理
如果您或者室友在路由器本身已经安装了 OpenClash / Nikki / PassWall2（把全屋设备接管了），您在手机连上该 Wi-Fi 后如果又把 Shadowrocket/FlClash 打开：
- 手机数据包在手机本地加密一次 → 发给家里软路由又撞上软路由代理规则拦截死锁 → **直接连不上或极慢**！
- **验证方法**：连上该 Wi-Fi 后，试着**彻底关掉手机里的本地代理开关**直接访问外网；如果直接能上外网，证明路由器已经负责了全屋透明代理，连此 Wi-Fi 时勿再叠加手机代理。

### 第 6 步：确认是不是校园网/酒店“门户认证超时”或跨网运营商互联障碍
在酒店、高铁站或学校连上 Wi-Fi 信号但其实还没有在弹出的浏览器登录页面点认证放行时，一切外网连接都会被门户拦截；此外极少数地方宽带（如特定二级长城宽带/广电宽带）对特定中转节点存在丢包阻断，这时建议参考 [节点全部超时排查手册](/troubleshooting/all-nodes-timeout/) 换用该机场里的其他地区或备用中转入口节点验证。

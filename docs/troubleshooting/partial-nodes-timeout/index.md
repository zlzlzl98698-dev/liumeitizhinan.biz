# 部分节点超时排查指南

**Answer-First 核心结论**：订阅中大部分香港、新加坡节点流畅，唯独少数节点（如冷门地区或某个单一编号节点）显示 **Timeout 超时或 0B/s**，通常属于 **单节点落地维护、特定入口与宽带运营商之间的路由抖动，或服务端刚替换了节点 IP**，并非客户端故障或机场整体跑路。

正确处置方式是“先更新、再绕行、不死磕”：
- **① 同步最新订阅**：先刷新一次订阅，获取服务商可能刚下发的新入口或修复后的节点 IP。
- **② 同区与同组轮换**：在同地区内换用其他编号节点（如 `香港01` 换 `香港05`），或切至匹配当前宽带的入口组。
- **③ 区分真实故障**：只有全订阅节点大面积超时时，才需要转去排查本地网络与客户端。

## 一、部分节点超时 Timeout：10 秒症状定位矩阵

| 症状现象 | 本质原因 | 优先处理方向 |
|---|---|---|
| 仅个别节点（如德国01/美国02）超时或 0B，其余正常 | 单台落地服务器临时维护、受攻击或跨洲线路抖动 | 更新一次订阅，直接手动切到同地区其他可用节点 |
| 某一家宽带（如移动）下某组入口全超时，换电信却正常 | 该入口节点与当前运营商跨网路由阻断或丢包严重 | 切往订阅内标注的 BGP 入口或匹配当前宽带的专属入口 |
| 测速全部显示超时，但选其中一个节点居然能打开网页 | 客户端测速 URL 被拦截或本地测速并发过高被网关限流 | 核对测速地址（如 `cp.cloudflare.com`），用浏览器实测 |
| 整个订阅 100% 节点全部变红超时，且无法更新订阅 | 订阅过期、本地断网、系统时间偏差或客户端配置损坏 | 转至 [节点全部超时排查](/troubleshooting/all-nodes-timeout/) |

## 二、分步骤排查与容错操作

### 1. 第一时间更新订阅排除服务端 IP 变更
服务商对高负载或被阻断的落地节点更换 IP 时，旧配置文件里依然保留着过期域名或 IP：
- 在 [Clash Verge Rev](/clients/clash-verge-rev/)「订阅」页点击对应订阅卡片右侧的 **刷新图标**，或右键选择「更新」；
- 在 [v2rayN](/clients/v2rayn/) 点击顶部菜单「订阅分组 → 更新当前订阅（不通过代理/通过代理视网络情况而定）」；
- 在 [Shadowrocket](/guides/shadowrocket-guide/) 首页向右滑动或点击订阅右侧刷新按钮，再重新执行一次真连接延迟测试（若更新订阅本身报错，请查看 [订阅更新失败排查](/troubleshooting/subscription-update-failed/)）。

### 2. 切换同地区备选节点与匹配运营商入口
1. **同地区编号轮换**：参考本站实测保留数据（如 `2026-08-11` 与 `2026-08-19` [光速云实测](/reviews/guangsu/)），同一套餐内出现少数节点（如个别欧美冷门线路）呈 0B/KB 级离散波动是正常现象，同一地区通常配有多个编号备份，优先切换至延迟最低的可用编号节点；
2. **调整入口地区匹配宽带**：如果您使用的机场在节点名称中区分了线路入口（如 `移动入口`、`电信入口`、`BGP 多线`），请务必依据自己当前所处的网络环境对应挑选，避免移动宽带硬连单线电信入口（详见 [三大运营商路由差异](/network/three-isp-routing/) 与 [BGP 中转与直连机制](/network/bgp-transit-vs-direct/)）。

### 3. 检查客户端测速逻辑避免误判
- **避免过高并发测速**：一次同时对上百个节点发起延迟测速，部分路由器防火墙或本地安全软件会误判为异常扫描并主动丢包；
- **核对测速目标地址**：在 Clash Verge Rev 设置中确认延迟测试 URL 使用稳定的 `http://www.gstatic.com/generate_204` 或 `http://cp.cloudflare.com/generate_204`，切勿填入已被阻断或失效的自定义网址。

## 三、部分节点超时 Timeout：恢复验收标准

- 手动切换至同地区其他编号节点或对应运营商入口后，测试延迟稳定在合理范围（亚洲节点通常 30–120ms），且网页和视频加载立即恢复；
- 若某特定节点更新订阅后连续超过 24 小时依然 0B 或超时，保留测试截图并向服务商工单反馈，避免将失效节点设为固定默认。

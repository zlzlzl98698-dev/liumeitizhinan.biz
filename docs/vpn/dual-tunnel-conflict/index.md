# VPN 和代理客户端能不能同时开启运行？路由冲突机制与安全共存方案

**Answer-First 核心结论**：**绝大多数场景下，不能同时打开“全流量接管模式”的 VPN（企业内网 VPN、传统海外商业 VPN 或全路由加速器）和开了 TUN 模式的代理客户端**——尤其是在 iPhone/Android 移动端，系统机制**绝对禁止两个 VPN 并发**（开一个必顶掉另一个）。但在 **Windows / macOS 桌面端**，可以通过 **“游戏/企业客户端走底层的进程/内网路由 + 代理客户端退回纯 HTTP 系统代理（关闭 TUN）+ 规则内放行内网段”** 实现可控共存，或者利用 **软路由网关做硬件级隔离** 彻底解决冲突。

---

## 一、底层为什么会冲突？一张图看懂两者的打架环节

想理解 VPN 与代理软件怎么共存，必须先分清 [VPN 与代理的本质差异](/vpn/vpn-vs-proxy/)，在操作系统网络层，冲突集中发生在三个地方：

| 冲突发生层面 | 传统 VPN / 游戏加速器 / TUN 模式动作 | 同时开启两者引发的典型故障 |
|---|---|---|
| **1. 操作系统路由表抢占** | 争先将默认网关路由权重（Metric）指向自己的虚拟网卡 | 数据包从 A 网卡发出后被 B 网卡二次拦截加密，或者干脆找不到真实物理路由器出口，全部超时断网 |
| **2. 移动端系统锁死单通道** | iOS / Android 系统限制同一时刻只能注册一个活跃 `VPN` 图标 | 当你在打开 Shadowrocket / FlClash 的瞬间，原先挂着的公司 VPN 或游戏加速器会被系统直接强制杀掉 |
| **3. DNS 服务器指向互相覆写** | VPN 写入企业内网 DNS，Clash 写入 Fake-IP (`198.18.0.2`) | 访问公司 OA / Git 内网域名直接解析出虚构 IP 连不上，或者外部 AI 访问反向触发公司安全网关拦截 |

## 二、桌面端 Windows / macOS 的 3 种正确共存方案

### 方案 A：工作必须开企业 VPN + 浏览器要上 Google/ChatGPT（不冲突改法）
1. **关闭代理客户端里的「TUN 模式」**，改回只使用 **「系统代理（System Proxy）」**；
   *(注：一旦关掉 TUN，命令行终端如果不配 `http_proxy` 环境变量则不会走机场，但 Chrome/Edge/VS Code 依然可以通过系统代理联网，且不再跟公司 VPN 抢虚拟网卡。)*
2. **在 Clash Verge Rev 全局扩展规则首位加白名单放行内网**：把公司的内网网段（如 `IP-CIDR,10.0.0.0/8,DIRECT,no-resolve`、`IP-CIDR,172.16.0.0/12,DIRECT,no-resolve`、`DOMAIN-SUFFIX,yourcompany.internal,DIRECT`）放进 `DIRECT`；
3. **启动顺序**：先连接企业内网 VPN 确认内网通畅 → 再打开 Clash 的「系统代理」开关，测试浏览器同时访问内网系统和外部网页是否双通。

### 方案 B：一边开 UU/雷神等游戏加速器打外服游戏，一边开 Discord / 看攻略网页
1. **同样千万别在 Clash 里开 TUN 模式**（否则两个驱动级驱动抢游戏 UDP 封包，游戏立刻高丢包或跳 Ping）；
2. 在游戏加速器设置中将加速模式选为 **「仅针对当前游戏进程代理（进程模式 / 模式一）」**，不要选全网卡全局路由；
3. Clash Verge Rev 只开启「系统代理」，Discord 和浏览器走系统代理，游戏本体直走加速器驱动——如果 Discord 语音也需要走代理但无法读取 HTTP 系统代理，可在 Discord 语音网络设置或通过游戏加速器自带的浏览器/平台附带加速解决，**勿双开双 TUN 网卡**。

### 方案 C：终极无冲突方案——硬件网关层隔离（软路由 + 本机 VPN）
如果您既是开发者重度依赖桌面端 TUN 接管所有终端/AI工具，又每天必须开着公司 VPN 办公：
- 在家里或桌面旁部署一台 **OpenWrt 软路由（OpenClash / Nikki / HomeProxy）**，由路由器负责全部海外分流与代理网关；
- **电脑端彻底卸载或关闭 Clash/v2rayN**，只连接公司内网 VPN（或仅跑单一所需隧道）——由于系统内部没有任何两个虚拟网卡抢路由，稳定性直接拉满。*(前提同样是您所选机场必须支持第三方通用订阅链接，不可选纯专属端品牌。)*

## 三、移动端（iOS / Android）遇到需要共存怎么办？

在手机系统底层限制面前（不能同时拉起两个 VPN 进程），有两条实用替代思路：
1. **合二为一（用现代通用客户端直接接管 WireGuard + 机场策略）**：如果您公司的内网 VPN 用的是标准 **WireGuard** 协议，在 iOS 的 **Shadowrocket / Surge / Stash** 或 **Mihomo/sing-box** 生态中，其实可以直接把公司的 WireGuard 节点和您的机场节点导入到同一个配置文件里！用分流规则实现“公司内网域名走 WireGuard 出口、海外业务走机场 IEPL 出口、国内走直连”，一条虚拟通道完成双网并行。
2. **双机或 Wi-Fi 旁路由辅助**：家里或办公室有一台设置好旁路由的备用机器时，手机只连 Wi-Fi（把网关/DNS 指向旁路由享受机场分流），手机本地腾出唯一 VPN 槽位单独挂公司内网软件或加速器即可。

## 四、如果不小心同时开了导致彻底断网，怎么一键救回？
如果刚才已经不小心同时打开并引发了全网无响应：
1. 先彻底退出其中一方（甚至两个都先点完全关闭）；
2. 若浏览器连百度都打不开，排查是否残留系统代理或虚拟网卡异常，详见 [连接成功却打不开网页排查](/troubleshooting/connected-no-internet/) 与 [TUN 模式异常修复指南](/troubleshooting/tun-mode-error/)。

# 电信 163、联通 4837 与移动 CMI 晚高峰选节点实操：从三网实测看延迟与带宽差异

**Answer-First 核心结论**：同一家机场在不同家庭宽带运营商手里体感差距天差地别——根源在于 **电信 163、联通 4837、移动 CMI** 三张骨干网特性与各省国际出口拥堵差异。

结合 **2026-08-19 三网同日实测对照** 与选线实操方法：
- **实测反常识规律**：**延迟低（TLS RTT 65ms）不代表 HTTPS 真正快（实际响应曾高达 1200ms+）**，且某一家运营商快到飞起的节点在另一家运营商下可能出现单地区波动。
- **三步选线实操**：① 核对机场国内入口是否多线 BGP → ② 在本地宽带下实测港/日/新单线程带宽 → ③ 为不同宽带备选两套地区分组。

## 一、三网跨境骨干路由的真实物理特征

在讨论机场的 IEPL 专线还是 BGP 中转之前，您本地宽带数据包离开小区光猫后的第一段路（国内运营商到机场国内入口，或直连模式下国内直接出海）就决定了 50% 的稳定性：

### 1. 中国电信（普通民用 163 骨干网 · AS4134）
- **核心特征**：市场占有率高，白天带宽充裕，但 **每晚 20:00–23:30 国际出海方向 163 骨干接口普遍高负载**。
- **选线规律**：电信用户如果直接买“公网直连（无国内入口中转、非 CN2 GIA/IEPL）”的便宜机场，晚高峰看欧美或普通日本机房 IP 往往丢包严重、YouTube 自动掉回 360p。**电信用户最依赖国内优质多线 BGP/电信专属入口转 IEPL 的机场**。

### 2. 中国联通（CU 169 / 4837 骨干网 · AS4837）
- **核心特征**：相对 163 而言民用出海国际带宽人均余量通常更宽松，过去对日本东京、新加坡及美西路径表现较友好，但部分北方省份在特定入口节点间仍会出现省际绕路或突发抖动。
- **选线规律**：联通用户切勿只迷信香港单个入口；在北方联通实测中，**日本（JP）、新加坡（SG）与台湾（TW）节点有时反而比过载的香港入口表现更稳**。

### 3. 中国移动（CMNET / CMI 移动国际 · AS9808/AS58453）
- **核心特征**：国内段下载吞吐能力强，近年大量扩建经过香港、新加坡的 CMI 国际传输，对亚太地区中转及特定落地机房表现出极高带宽上限；但在某些冷门欧美路线或严格 UDP 防火墙限制区域偶有突发单节点限速或断流（俗称“QOS/阻断”）。
- **选线规律**：移动用户在**香港、新加坡、日本**三条线经常跑出三网最高峰值，但同时更需要留意欧洲或冷门节点的可用性测试。

## 三、为什么客户端“测速延迟 30ms”但实际用起来依然很卡？

这是日常使用和排查问题时最高频的认知误区。点击 Clash Verge Rev 或 Shadowrocket 的延迟测试按钮，结果往往呈现绿色 `45ms`、`60ms`，可打开网页或看视频却一直转圈，原因通常有四类：

1. **只测了握手，没测大包吞吐（TCP Window / 丢包重传）**：URL Test 发送一个极小的 HTTPS `GET generate_204` 请求，只要几百字节返回 204 就算成功；但看 4K 视频需要每秒稳定传输 3–6 MB 的连续数据流。一旦骨干链路上出现 3%–5% 丢包，单线程 TCP 拥塞控制窗口会迅速塌缩，实际下载速度直接掉到几百 KB/s。
2. **中转入口与你本地跨网绕道**：比如机场中转服务器只接了广东移动单线入口，电信用户晚高峰走跨网 163 互联过去，可能握手包勉强挤过来了，后续大包却在省际网间互联点大量排队丢包。
3. **节点名称标注为“电信专属”但您挂着联通/移动宽带去连**：部分订阅里专门为电信优化的独立入口节点（如“电信入口-香港01”），非电信用户连上去反而可能因为路由不对称导致高抖动或阻断。
4. **本地路由器或光猫缓冲区膨胀（Bufferbloat）**：家里有人在用满速下载网盘或开上传做种，把小区上行带宽堵死，导致所有跨境小包全部排队延迟暴涨。

## 四、三网宽带用户在晚高峰选节点的 4 步实操方法

1. **第 1 步：区分节点命名里的入口与用途提示**
   收到订阅后先浏览节点列表前缀：如果看到 `电信专线`、`移动优化`、`BGP`、`IEPL` 等字样，优先挑选与自己宽带运营商匹配（或全网多线 BGP 入口）的集群。
2. **第 2 步：在晚上 20:30–22:00 用“真实单线程速度”筛一遍主力 3 国**
   不要只在早上或下午测一次！找一个工作日晚间九点，打开 YouTube 找一条 4K60fps 测试视频，右键打开「详细统计信息（Stats for nerds）」，观察 **Connection Speed** 栏位能否在香港、日本、新加坡三组中稳定在 **25,000 Kbps（约 25Mbps）以上**，且 Buffer Health 持续上升。
3. **第 3 步：建立 `url-test` 故障兜底组，但把 AI 分组独立锁定**
   - 视频与日常浏览组（`Streaming / Auto`）可以放在 `fallback` 或手动挑选高带宽地区组（如港/新/日）；
   - ChatGPT、Claude 与登录银行类业务则必须使用 `Select` 分组锁死通过测试的单一新加坡/美国/日本优质节点（配置方法见 [Claude 防封号锁单节点指南](/guides/claude-fixed-node-rules/)），防止因晚高峰抖动切来切去引发风控封号。
4. **第 4 步：交叉配合手机 5G 网络验证“到底是不是宽带背锅”**
   如果某晚所有港日节点全部在家里 Wi-Fi 慢到爬行，用手机关掉 Wi-Fi、打开 5G 蜂窝网络测同一条节点。如果 5G 秒开而家庭宽带卡死，问题 90% 出在当前时段你本地宽带的跨境互联波动或光猫/路由器负载上（详见 [晚高峰卡顿优化](/troubleshooting/peak-hour-congestion/) 与 [所有节点超时排查](/troubleshooting/all-nodes-timeout/)）。

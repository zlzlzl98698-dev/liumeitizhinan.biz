# Max (原 HBO Max) 使用指南：可用地区覆盖与原生 IP 要求

**Answer-First 核心结论**：**Max（原 HBO Max）** 已从早期仅限欧美拓展至北美、拉美、部分欧洲及新加坡、香港、台湾等亚太市场，但平台对 **非服务区 IP、普通机房 IP 及旧版分流规则漏流** 拦截极严。能否顺利登录看剧，取决于 **支持地区对齐、域名规则更新与 IP 纯净度** 三重保障。

- **区域版图更新**：亚太已支持新加坡、香港、台湾等节点区域，但不同大区的 **App 入口、计费渠道与片库目录** 仍存在明显区分。
- **防漏流关键**：必须确保分流规则覆盖新版 **`max.com`** 与 **`discomax.com`** 全套域名，并配合 TUN 模式消除本地 DNS 与 IPv6 泄漏。

## 二、常见“地区不可用”与无法加载的 4 步排查

1. **检查并升级代理分流规则集**：许多老旧订阅或本地自定义规则只写了 `hbomax.com`。请务必在客户端规则中确认包含 `max.com`、`hbomax.com`、`discomax.com` 及相关 Warner Bros. Discovery 媒体域名，或直接使用近期持续更新的权威规则集（配置原则见 [流媒体分流优化指南](/guides/streaming-optimization/)）。
2. **核实节点是否真正解锁 Max（勿轻信盲测）**：并非能看 YouTube 就能看 Max，普通数据中心出口常常在登录校验阶段直接拒访。可在 [流媒体与 AI 测试记录中心](/tools/streaming-check/) 核对各品牌的实测证据与厂商资料差异；注意未经过独立截图验证的节点，上线前应先用无痕窗口小范围实测。
3. **开启 TUN 模式并彻底关闭 IPv6**：Max 客户端与网页端一旦检测到本机通过国内宽带 IPv6 泄漏通信，会立刻拒绝加载播放列表。请在 [Clash Verge Rev](/guides/clash-mihomo-guide/) 等客户端中开启 TUN 模式、配置 `ipv6: false` 并使用 Fake-IP（详见 [TUN 与 DNS 防泄漏指南](/guides/tun-and-dns/)）。
4. **排查浏览器插件、时区与脏 Cookie**：如果你曾在错误节点下打开过 Max，浏览器缓存的定位标记会导致切换新节点后依然报错。此时应清除站点 Cookie 后改用无痕模式测试，并暂时关闭强力反指纹或脚本拦截插件，同时确保设备系统时间与标准时间一致。
